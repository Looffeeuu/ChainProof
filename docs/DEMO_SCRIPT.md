# ChainProof 答辩演示脚本（7 分钟）

本脚本同时用于**现场演示**、**演示视频录制**和**计时彩排**。全部操作都走真实 Fabric 网络，不手工修改账本。

## 1. 演示前准备（提前 15 分钟）

### 1.1 重置环境

```bash
cd ~/ChainProof/backend
npm run demo:reset          # 提示时输入 yes，约 3–5 分钟
```

结束时记下 seed 输出的两张证书 ID（`alice @ P001`、`bob @ P002`）。

确认后端正常：

```bash
curl http://127.0.0.1:3000/api/health
```

### 1.2 启动前端（新终端）

```bash
cd ~/ChainProof/frontend
cat > .env.local <<'EOF'
VITE_REAL_APIS=*
VITE_API_TARGET=http://127.0.0.1:3000
VITE_DEMO_MEMBERS=alice,bob,charlie,dave
EOF
npm run dev
```

### 1.3 桌面准备

- 浏览器打开 `http://localhost:5173/`，身份切到 **alice**，缩放 100%，窗口宽度 ≥ 1280。
- 桌面放两个文件：
  - `答辩成果-v1.pdf`：现场要提交的成果文件（任意小文件即可）。
  - `答辩成果-v1-改.pdf`：把上一个文件复制后随便改一个字节，用来演示「篡改可被发现」。
- 准备好的标签页：`/verify/CP-DEMO-NOT-FOUND`。
- 关闭系统通知；录屏时隐藏书签栏。

## 2. 演示流程

| # | 时间 | 身份 | 操作 | 讲解要点 |
|---|---|---|---|---|
| 1 | 0:00–0:30 | alice | 打开**概览**，指出 3 个项目、已验证 / 待确认 / 已拒绝三种状态 | 「这是 3 人团队在 ChainProof 上的真实记录，每一条状态都来自 Fabric 账本。」 |
| 2 | 0:30–1:15 | alice | 进入 **VLA 安全性基准测试（P001）**：贡献面板 → 时间线 → 点开一条记录的「链上交易」txId | 「累计比例只统计全员确认过的里程碑；被拒绝和待确认的不计入。每条记录都能对应到一笔 Fabric 交易。」 |
| 3 | 1:15–1:45 | alice | 点**创建项目**：名称「答辩现场演示」，成员 alice、bob、charlie → 创建 | 「项目和成员列表直接写链，返回交易 ID。」 |
| 4 | 1:45–2:45 | alice | **提交里程碑**：标题「最终成果 v1」，选择 `答辩成果-v1.pdf`，指出页面立刻算出的 SHA-256；比例 alice 50 / bob 30 / charlie 20 → **提交并存证** | 「哈希在浏览器本地算一次，后端收到原始字节后再独立算一次，两边一致才写链。链上只存哈希，文件留在链下。」 |
| 5 | 2:45–3:05 | alice | 打开刚提交的里程碑 | 「提交者本人没有确认按钮——自己不能给自己作证，这条规则写在链码里。」 |
| 6 | 3:05–4:05 | bob | 切身份到 **bob**，打开该里程碑：**下载原文件** → 把下载的文件拖入核对框，显示「一致」；再拖入 `答辩成果-v1-改.pdf`，显示不一致 → 最后点**确认这份声明** | 「确认人先拿到原文件，在本地核对它就是链上登记的那一份。哪怕只改一个字节，哈希也完全不同。」 |
| 7 | 4:05–4:30 | charlie | 切身份到 **charlie**，点**确认这份声明**，状态变为**链上已验证**，出现新的 txId | 「全部确认人通过才是 VERIFIED；任何一人拒绝就整条作废，表态不能撤回。」 |
| 8 | 4:30–5:00 | charlie → alice | 回到项目页，看时间线和贡献面板更新为 50 / 30 / 20 | 「统计全程使用整数运算 + 最大余数法，保证每个背书节点结果一致，总和严格为 100%。」 |
| 9 | 5:00–5:45 | alice | 点**签发我的贡献证明** → 证书页 → **去验证这份证书**，显示「证书有效」 | 「证书引用了参与的里程碑和链上交易，外部的人不用登录就能核验。」 |
| 10 | 5:45–6:05 | 任意 | 打开 `/verify/CP-DEMO-NOT-FOUND` | 「伪造的编号查不到，返回 NOT_FOUND，而不是报错。」 |
| 11 | 6:05–6:35 | dave → charlie | 切到 **dave**（非成员）打开 `/milestones/M004`：看不到下载按钮；切到 **charlie** 打开**答辩演示脚本（P003）**，签发按钮不可用，提示「累计贡献比例为 0%」 | 「非成员拿不到原文件，后端直接 403；没有被确认贡献的人签不出证书。」 |
| 12 | 6:35–7:00 | — | 回到 PPT 总结页 | 一句话收尾：「ChainProof 把成果、比例和他人的确认绑在一起上链，让贡献可以被独立核验。」 |

> 时间紧张时优先压缩第 2 步和第 11 步；第 4、6、7、9 步是核心闭环，不要跳过。

## 3. 现场备用方案

| 情况 | 处理 |
|---|---|
| Fabric 起不来 / 后端 500 | 立刻改放演示视频；视频即按本脚本录制 |
| 写链较慢（> 5 秒） | 边等边讲第 4 步的双哈希原理，不要重复点击 |
| 网络或电脑整体故障 | 删除 `frontend/.env.local` 后 `npm run dev`，切到 Mock 模式讲解界面，并说明数据为 Mock |
| 被问「能不能直接改账本」 | 打开时间线中的 txId，说明状态变更只能通过链码交易，且确认规则由链码强制 |

## 4. 演示视频录制要求

- 分辨率 1920×1080，录屏软件可用 OBS 或 Windows 自带「截图工具 → 录制」。
- 严格按第 2 节流程录制，总长 ≤ 7 分钟；配音可以后期补。
- 录制前执行一次 `npm run demo:reset`，保证数据与脚本一致。
- 文件命名 `ChainProof-演示视频.mp4`，**不要提交到 Git 仓库**，放入最终提交包（见第 6 节）。

## 6. 最终打包

在仓库根目录执行：

```bash
bash scripts/package-delivery.sh
```

脚本会先做敏感信息检查，再把当前 `HEAD` 的源码（不含 `node_modules`、`.env`、账本和上传文件）打包，并把 `delivery/` 目录下的 PPT、视频一并放入 `dist-delivery/ChainProof-交付包-<日期>.zip`。
